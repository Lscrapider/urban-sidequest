# 发现页城市切换设计

## 目标

发现页首次进入仍以设备定位作为默认城市；用户可随时从右上角城市入口改为手动选择地区，并能主动切回当前位置。拒绝定位授权时，不展示默认北京等不真实城市，而是进入“无权限”状态。

## 交互方案

右上角城市胶囊始终可点击（定位请求进行中除外），点击后打开“切换城市”底部面板：

- **使用当前位置**：已有定位权限时重新定位；没有权限时关闭切换面板并展示现有的定位授权提示。
- **手动选择地区**：直接打开现有地区选择器，不要求定位权限。

首次进入时，若没有手选地区记录，仍按设备定位流程确定城市。用户手动选择地区后，该选择会保存在本地，并在后续进入发现页时优先恢复；用户选择“使用当前位置”并成功定位后，清除手选地区记录，恢复“默认随定位”的行为。

## 无权限状态

用户拒绝系统定位授权，或关闭应用内授权提示而未授权时：

- 若没有已保存的手选地区，发现页城市展示为“无权限”，天气展示为“选择地区后显示天气”，不再回退到北京或任何默认天气。
- 若已保存或本次刚选择了手动地区，手动地区仍是有效探索锚点，展示该地区并正常加载对应天气。
- 用户可随时点击右上角入口，选择“手动选择地区”；也可选择“使用当前位置”再次请求授权，永久拒绝时沿用“去设置”入口。用户从系统设置返回后会重新检查权限，授权成功则自动继续定位。

## 状态与数据流

`DiscoverViewModel` 保持探索锚点、城市切换面板可见状态和定位授权状态：

1. 初始化：优先恢复已保存的手动锚点；没有手动锚点时，有权限则定位，无权限则展示授权提示。
2. 点击城市入口：仅展示切换面板，不直接重新定位。
3. 选择当前位置：有权限则定位并清除手动锚点；无权限则进入授权提示。系统权限请求在应用内提示关闭后触发，避免两个弹窗重叠。
4. 选择地区：打开现有地区树；选中后保存手动锚点、关闭相关面板并刷新该地区天气。
5. 拒绝授权：先进入“无权限”展示状态，同时保留授权提示中的“选择地区”入口；关闭该提示后停留在“无权限”状态。若没有手动锚点，不重复弹出授权提示。

UI 层只渲染状态并派发事件；定位、持久化和天气刷新继续由 ViewModel 与 Repository 负责。现有两小时天气缓存策略不变。

## 边界与验证

- 不改变地图入口、路线参数、地区接口和天气缓存契约。
- 不新增单元测试，遵循项目约束；实现后运行现有 Android Kotlin 编译任务并检查 diff 格式。
- 不启动前端服务或浏览器；真机权限弹窗与系统设置跳转保留为手工验收项。
