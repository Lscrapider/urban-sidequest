# 城市副本项目流程文档

## 1. 流程目标

本项目按“先产品与 UI，后技术与开发”的顺序推进。流程不是一次性定死，设计和实现会互相校正；但每个阶段都要沉淀到文档，避免想法只留在对话里。

核心原则：

- 先做 UI 设计和页面信息架构。
- UI 设计过程中产生的新产品想法，及时回写产品设计文档。
- 产品页面稳定后，再定义技术架构和技术选型。
- 技术架构确定后，先搭模块骨架。
- 模块骨架完成后，再按页面逐步开发。

## 2. 阶段一：UI 设计

目标：先把用户看到和操作的界面想清楚。

主要工作：

- 梳理 Android App 核心页面。
- 梳理 Web 后台和产品介绍页。
- 参考 `docs/ui-inspiration.md`，提炼可用的页面结构和交互方式。
- 产出页面设计文档，例如 `docs/page-design.md`。
- 明确每个页面的目标、入口、状态、关键组件和数据需求。

需要覆盖的核心页面：

- 地图选区页。
- 条件输入页。
- 路线结果页。
- POI 详情弹窗。
- 路线执行与打卡页。
- 完成反馈页。
- Web 后台基础页面。
- 产品介绍页。

## 3. 阶段二：产品设计回写

目标：UI 设计过程中出现的新产品判断，要回写到产品文档。

触发条件：

- UI 设计发现原流程不顺。
- 页面信息层级改变了产品优先级。
- 某个交互需要新增或调整产品能力。
- 某个字段或状态变成核心体验。
- 发现原设计过细、过重或不适合第一阶段。

回写位置：

- 产品体验和功能边界写入 `docs/product-design.md`。
- UI 启发和视觉参考写入 `docs/ui-inspiration.md`。
- 页面结构和组件信息写入 `docs/page-design.md`。
- 技术约束不写入产品文档，单独写入 `docs/technical-design.md`。

## 4. 阶段三：技术架构和选型

目标：在页面结构清楚后，再定义技术方案，避免接口和模块脱离真实页面。

主要工作：

- 明确 Android App 技术栈。
- 明确后续 iOS App 的兼容策略。
- 明确后端技术栈。
- 明确 Web 后台技术栈。
- 定义系统模块边界。
- 定义核心数据模型。
- 定义 API 契约。
- 定义异步任务、缓存、限流和失败降级方案。
- 定义用户隔离、权限和信息安全策略。

产出：

- 更新 `docs/technical-design.md`。
- 新增或更新 `docs/architecture.md`。
- 新增或更新 `docs/api-design.md`。

技术选型需要服务当前目标：先跑通路线生成闭环，再逐步增强。

## 5. 阶段四：开发模块构建

目标：先搭可扩展的模块骨架，不急着堆完整业务。

建议模块：

- Android App 页面模块。
- Web 后台页面模块。
- 用户与权限模块。
- 地图区域与 POI 模块。
- 路线生成任务模块。
- 路线结果模块。
- POI 解释卡模块。
- 打卡与反馈模块。
- 第三方服务适配模块。

模块构建要求：

- 先定义边界和数据结构。
- 先跑通 mock 链路。
- 第三方地图、天气、LLM 能力先做适配层，不直接散落在业务代码中。
- 用户数据、路线数据和后台管理数据保持隔离。

## 6. 阶段五：按页面开发

目标：按用户真实路径推进开发，而不是按技术模块孤立开发。

推荐顺序：

1. 地图选区页。
2. 条件输入页。
3. 路线生成任务提交。
4. 路线结果页。
5. POI 详情弹窗。
6. 路线执行与打卡页。
7. 完成反馈页。
8. Web 后台基础维护页。
9. 产品介绍页。

每开发一个页面，需要同步确认：

- 页面目标是否清楚。
- 页面状态是否完整。
- 页面需要的数据是否在接口中。
- 错误、加载、空状态是否有处理。
- 是否影响产品设计文档或技术设计文档。

## 7. 阶段六：文档和 README 维护

目标：让项目随时能被重新理解和接手。

需要维护：

- `README.md`：项目入口、当前状态、文档索引、开发流程。
- `docs/product-design.md`：产品设计基准。
- `docs/ui-inspiration.md`：UI 启发和参考图。
- `docs/page-design.md`：页面设计和信息架构。
- `docs/technical-design.md`：技术约束和架构原则。
- `.gitignore`：忽略本地环境、依赖、构建产物和临时文件。

README 不替代详细文档，只作为项目导航。

## 8. 当前推荐下一步

当前项目已经有产品设计、技术设计和 UI 启发文档。下一步建议：

1. 编写 `docs/page-design.md`。
2. 明确 Android App 核心页面的信息架构。
3. 根据页面设计更新 `docs/product-design.md`。
4. 再进入技术架构和选型。
