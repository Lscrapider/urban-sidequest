# 用户画像问卷与画像表设计

本文记录 Urban Sidequest v1 用户画像的问卷设计、数据库表设计、写入流程和默认测试画像。

本文只定义 **问卷冷启动画像**，不实现行为学习画像，不实现 Linear Ranker 计算，也不设计前端 UI 细节。

## 1. 目标和边界

用户画像用于 POI 预筛阶段 Linear Ranker 的 `userPreferenceVector` 来源组。

v1 约束：

```text
用户画像来自问卷，不来自行为数据。
画像只作为 derivedFeature 的 cross 原料，不直接提供独立打分列。
tagCode 必须对齐 interest_tag_catalog.tag_code。
不把每个 tag 展开成动态 X 列，避免 X 维度随 catalog 变化。
新用户或未完成问卷时 profileConfidence=0，个性化自然收缩为 0。
```

与路线请求的边界：

```text
RouteGenerateParam.interestTags:
  本次路线短期兴趣，进入 interestMatchRatio。

userPreferenceProfile.tagAffinity:
  用户长期兴趣，进入 userInterestAffinity。
```

两者不可混用。

## 2. 数据库表设计

旧 `user_preferences` 表不再承担画像职责。若环境可重建数据库，可直接从初始迁移中移除；
若已有环境跑过旧迁移，应在新迁移中执行 `DROP TABLE IF EXISTS user_preferences;` 后创建以下两张表。

### 2.1 user_preference_profiles

一人一行，保存固定维度的长期偏好。

```sql
CREATE TABLE user_preference_profiles (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id),
    distance_sensitivity NUMERIC(3, 2) NOT NULL DEFAULT 0,
    budget_sensitivity NUMERIC(3, 2) NOT NULL DEFAULT 0,
    transfer_sensitivity NUMERIC(3, 2) NOT NULL DEFAULT 0,
    hidden_gem_affinity NUMERIC(3, 2) NOT NULL DEFAULT 0,
    profile_confidence NUMERIC(3, 2) NOT NULL DEFAULT 0,
    questionnaire_version VARCHAR(32) NOT NULL DEFAULT 'v1',
    completed_at TIMESTAMPTZ,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    CONSTRAINT uk_user_preference_profiles_user UNIQUE (user_id),
    CONSTRAINT ck_user_preference_profiles_ratio CHECK (
        distance_sensitivity BETWEEN 0 AND 1
        AND budget_sensitivity BETWEEN 0 AND 1
        AND transfer_sensitivity BETWEEN 0 AND 1
        AND hidden_gem_affinity BETWEEN 0 AND 1
        AND profile_confidence BETWEEN 0 AND 1
    )
);

CREATE INDEX idx_user_preference_profiles_user_id
    ON user_preference_profiles (user_id);
```

字段含义：

| 字段 | 含义 | Linear 去向 |
| --- | --- | --- |
| `distance_sensitivity` | 距离敏感度 | `personalizedDistancePressure` |
| `budget_sensitivity` | 预算敏感度 | `personalizedBudgetPressure` |
| `transfer_sensitivity` | 换乘敏感度 | `personalizedTransitPressure` |
| `hidden_gem_affinity` | 小众探索偏好 | `personalizedExplorationMatch` |
| `profile_confidence` | 问卷置信度/完成度 | profileCross 全局收缩乘子 |
| `questionnaire_version` | 问卷版本 | 迁移和回放用 |
| `completed_at` | 最近一次完成时间 | trace / 运营分析 |

### 2.2 user_preference_tag_affinities

一人多行，保存长期兴趣 tag 权重。`tag_code` 必须来自 `interest_tag_catalog.tag_code`。

```sql
CREATE TABLE user_preference_tag_affinities (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id),
    tag_code VARCHAR(64) NOT NULL REFERENCES interest_tag_catalog(tag_code),
    affinity NUMERIC(3, 2) NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    CONSTRAINT uk_user_preference_tag_affinities_user_tag UNIQUE (user_id, tag_code),
    CONSTRAINT ck_user_preference_tag_affinities_affinity CHECK (affinity BETWEEN 0 AND 1)
);

CREATE INDEX idx_user_preference_tag_affinities_user_id
    ON user_preference_tag_affinities (user_id);

CREATE INDEX idx_user_preference_tag_affinities_tag_code
    ON user_preference_tag_affinities (tag_code);
```

说明：

```text
affinity=0 的 tag 不需要落库。
tag 下线后历史行可保留，但加载画像时只使用 enabled catalog 中仍有效的 tag。
```

## 3. 问卷设计

问卷只采集长期偏好，避免询问“这次想去哪”。本次路线目标仍由路线生成页提供。

### 3.1 兴趣偏好

展示 `interest_tag_catalog.enabled = true` 的标签，用户对每个标签选择偏好强度。

| 选项 | affinity |
| --- | ---: |
| 很喜欢 | 1.00 |
| 感兴趣 | 0.70 |
| 可接受 | 0.40 |
| 不感兴趣 / 未选择 | 0 |

后端保存时：

```text
affinity > 0 才写入 user_preference_tag_affinities。
tagCode 必须存在于 enabled interest_tag_catalog。
```

### 3.2 距离敏感度

问题：你对走远路或绕远的接受度？

| 选项 | distanceSensitivity |
| --- | ---: |
| 很能接受 | 0.20 |
| 一般 | 0.50 |
| 比较敏感 | 0.80 |
| 非常敏感 | 1.00 |

### 3.3 预算敏感度

问题：你希望路线控制消费吗？

| 选项 | budgetSensitivity |
| --- | ---: |
| 不太在意 | 0.20 |
| 正常控制 | 0.50 |
| 偏低预算 | 0.80 |
| 严格低预算 | 1.00 |

### 3.4 换乘敏感度

问题：你能接受复杂交通或换乘吗？

| 选项 | transferSensitivity |
| --- | ---: |
| 可以接受 | 0.20 |
| 一般 | 0.50 |
| 尽量少换乘 | 0.80 |
| 不想换乘 | 1.00 |

### 3.5 小众探索偏好

问题：你喜欢小众、本地、非热门地点吗？

| 选项 | hiddenGemAffinity |
| --- | ---: |
| 不喜欢 | 0 |
| 偶尔可以 | 0.35 |
| 比较喜欢 | 0.70 |
| 很喜欢 | 1.00 |

## 4. profileConfidence 计算

v1 使用简单完成度规则：

| 问卷状态 | profileConfidence |
| --- | ---: |
| 兴趣偏好和四个敏感度全部填写 | 1.00 |
| 只填写兴趣偏好，未填写敏感度 | 0.60 |
| 只填写部分敏感度，未填写兴趣偏好 | 0.40 |
| 未填写问卷 | 0 |

注意：

```text
profileConfidence 是全局收缩乘子，不单独进入 W。
新用户 profileConfidence=0 时，W_personalization 全部自然为 0。
```

## 5. 写入流程

保存问卷时使用事务。

### 5.1 upsert profile

```sql
INSERT INTO user_preference_profiles (
    user_id,
    distance_sensitivity,
    budget_sensitivity,
    transfer_sensitivity,
    hidden_gem_affinity,
    profile_confidence,
    questionnaire_version,
    completed_at
)
VALUES (
    :userId,
    :distanceSensitivity,
    :budgetSensitivity,
    :transferSensitivity,
    :hiddenGemAffinity,
    :profileConfidence,
    'v1',
    now()
)
ON CONFLICT (user_id)
DO UPDATE SET
    distance_sensitivity = EXCLUDED.distance_sensitivity,
    budget_sensitivity = EXCLUDED.budget_sensitivity,
    transfer_sensitivity = EXCLUDED.transfer_sensitivity,
    hidden_gem_affinity = EXCLUDED.hidden_gem_affinity,
    profile_confidence = EXCLUDED.profile_confidence,
    questionnaire_version = EXCLUDED.questionnaire_version,
    completed_at = EXCLUDED.completed_at,
    updated_at = now();
```

### 5.2 replace tag affinities

用户取消某些兴趣时，旧 tag 权重必须消失。因此 v1 用“先删后插”。

```sql
DELETE FROM user_preference_tag_affinities
WHERE user_id = :userId;

INSERT INTO user_preference_tag_affinities (
    user_id,
    tag_code,
    affinity
)
VALUES
    (:userId, :tagCode, :affinity);
```

批量插入前校验：

```text
tagCode 必须存在于 enabled interest_tag_catalog。
affinity / sensitivity 必须 clamp 到 [0,1]。
affinity=0 不写入。
```

## 6. 读取流程

路线生成时按登录用户读取：

```text
authenticatedUser.id
  -> user_preference_profiles
  -> user_preference_tag_affinities
  -> RouteGenerationContext.userPreferenceProfile
```

无记录时构造空画像：

```text
tagAffinity = {}
distanceSensitivity = 0
budgetSensitivity = 0
transferSensitivity = 0
hiddenGemAffinity = 0
profileConfidence = 0
isNewUser = true
```

Linear extractor 后续固定生成 5 个 profileCross：

```text
userInterestAffinity
personalizedDistancePressure
personalizedBudgetPressure
personalizedTransitPressure
personalizedExplorationMatch
```

不展开动态 tag 列。

## 7. 默认测试画像角色

以下角色只用于本地调试、seed 或手动插入验证。它们不是产品角色，也不应该直接暴露给用户。

### 7.1 CITY_CLASSIC_PHOTO

适合验证经典景点、展馆、拍照点是否被个性化抬高。

```text
distanceSensitivity = 0.40
budgetSensitivity = 0.30
transferSensitivity = 0.40
hiddenGemAffinity = 0.20
profileConfidence = 1.00

tagAffinity:
  SCENIC = 1.00
  PHOTO = 0.90
  MUSEUM = 0.70
```

### 7.2 LOCAL_FOOD_EXPLORER

适合验证本地餐饮、夜市、小众本地街区是否被抬高。

```text
distanceSensitivity = 0.50
budgetSensitivity = 0.50
transferSensitivity = 0.40
hiddenGemAffinity = 0.85
profileConfidence = 1.00

tagAffinity:
  FOOD = 1.00
  LOCAL = 0.90
  NIGHT = 0.60
```

> `LOCAL` 已通过 catalog seed 作为有效 `tagCode`，可直接用于本角色的测试画像。

### 7.3 LOW_BUDGET_WALKER

适合验证预算压力、远距离压力和免费/低价点的相对优势。

```text
distanceSensitivity = 0.85
budgetSensitivity = 1.00
transferSensitivity = 0.70
hiddenGemAffinity = 0.40
profileConfidence = 1.00

tagAffinity:
  SCENIC = 0.70
  COFFEE = 0.50
  FOOD = 0.40
```

### 7.4 NIGHT_LIGHT_ROUTE

适合验证夜游、夜景、夜市和交通可达的组合。

```text
distanceSensitivity = 0.60
budgetSensitivity = 0.40
transferSensitivity = 0.80
hiddenGemAffinity = 0.60
profileConfidence = 1.00

tagAffinity:
  NIGHT = 1.00
  FOOD = 0.70
  PHOTO = 0.60
```

### 7.5 QUIET_CULTURE_REST

适合验证安静、展馆、咖啡休息类 POI 的个性化效果。

```text
distanceSensitivity = 0.55
budgetSensitivity = 0.45
transferSensitivity = 0.50
hiddenGemAffinity = 0.30
profileConfidence = 1.00

tagAffinity:
  MUSEUM = 1.00
  COFFEE = 0.80
  SCENIC = 0.40
```

## 8. 后续实现顺序

建议按以下顺序落地：

```text
1. 删除旧 user_preferences 表。
2. 创建 user_preference_profiles / user_preference_tag_affinities。
3. 新增 PO / Mapper / Manage。
4. 新增保存问卷接口。
5. 新增 LoadUserPreferenceProfileStep，把画像写入 RouteGenerationContext。
6. Linear extractor 消费画像，生成固定 5 个 profileCross。
```

第 6 步之前，不需要实现任何 Linear 打分逻辑。
