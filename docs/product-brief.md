# Product Brief: 城市副本

目标：做一个基于中国地图的城市探索副本生成器。

核心体验：
用户在中国地图上逐级选择省、市、区县，最大范围到区县级。选择区域后，可以配置副本类型和约束，比如美食、景点、展馆、拍照、夜游、低预算、约会、一个人、出发时间、可用时长、预算、出行方式、天气、社交强度、是否冷门。

系统根据 POI、路径规划、天气、时间、预算和用户偏好生成一条“一天的任务线”。副本包括先去哪、再去哪、每个点做什么任务、路径怎么走、每段预计耗时、备选方案。

MVP 主链路：
1. 选择区域：省 -> 市 -> 区县。
2. 选择副本条件：主题、时间、预算、出行方式、偏好。
3. 生成副本：一条包含多个地点和任务的路线。
4. 展示结果：地图路线 + 时间线 + 任务卡。
5. 完成反馈：好玩度、节奏、惊喜、尴尬、出片、是否推荐。

第一版技术建议：
- 不要一开始做强化学习或 DPO。
- 先用规则打分 + POI 候选池 + 路径规划 + LLM 编排。
- 后续再用用户反馈做偏好排序、DPO 或 contextual bandit。

数据来源：
- 高德/腾讯/百度地图开放平台：行政区划、POI、路径规划。
- 天气 API：天气、温度、降雨等环境因素。
- 不依赖大众点评/美团评价作为核心，因为评价数据难以稳定合法获取。
- 自建“副本体验分”：用户评价副本，而不是评价店铺。
- 当前阶段可先使用高德等地图平台评分和基础 POI 信息；大众点评、小红书等外部 UGC 平台仅作为备用跳转入口，不抓取、不聚合作为核心数据。
- 产品必须保留自建 UGC 能力，从路线反馈、POI 体验反馈、打卡内容和跳过/替换原因开始沉淀。

推荐算法初版：
score =
距离成本 * -0.25
+ 时间适配 * 0.20
+ 类型多样性 * 0.20
+ 冷门/新鲜度 * 0.15
+ 天气适配 * 0.10
+ 任务可玩性 * 0.10

产品重点：
这不是点评推荐，也不是旅行攻略，而是把现实城市变成一个轻量游戏。核心资产是副本模板、用户完成记录、体验评分和私人城市地图。
